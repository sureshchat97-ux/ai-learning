from decimal import Decimal
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()
_store: dict[str, "Invoice"] = {}

class Invoice(BaseModel):
    id: str
    vendor: str
    total: Decimal = Field(gt=0)        # validation, like a FluentValidation rule
    currency: str = "USD"

@app.post("/invoices", status_code=201)
async def create(inv: Invoice) -> Invoice:   # body parsed and validated for you
    _store[inv.id] = inv
    return inv

@app.get("/invoices/{inv_id}")
async def get(inv_id: str) -> Invoice:
    if inv_id not in _store:
        raise HTTPException(404, "Invoice not found")
    return _store[inv_id]

How an LLM works

You need the working intuition, not the math. Six ideas cover most interview questions.

One step of generation
Your text"Pay invoice INV-2041 by"
Tokenizertext → token IDs
Embeddingseach ID → a vector
Transformer layersattention mixes context
Probabilitiesfor every possible next token
Sample one" Friday"
↺ Append the token and run again, one token at a time, until a stop token or max_tokens
Tokens are word pieces, not words
Invoice INV-2041 total $1,250.00 due net-30

An illustrative split. Every tokenizer splits text differently. IDs and numbers break into many tokens, which is one reason models make arithmetic mistakes.

English≈4 ch
1 token≈¾ word

Rules of thumb for English text. You pay per token, and the context limit is counted in tokens.

Temperature reshapes the odds

"Please pay the attached ___". Probabilities from softmax(logits ÷ T), with logits 3.0, 2.0, 1.0, 0.5.

Low T for extraction and classification. Higher T for brainstorming.

The context window is a budget you split
System promptTool definitionsRetrieved documentsConversation historyRoom for the answer

An example split. Input and output share one limit, so a long prompt leaves less room for the answer. Quality also drops when key facts are buried in the middle of a very long context.

Tk

Token

The unit the model reads, writes and bills in.

Price and limits are per token, so measure them.

Cx

Context window

The maximum number of tokens in one request, input plus output.

The model remembers nothing between calls. You resend history every time.

T

Temperature

How random the sampling is. 0 means close to deterministic.

Even T=0 can vary slightly between runs. Design for it.

Em

Embedding

A list of numbers that captures meaning. Similar text gets nearby vectors.

The core of search in Book 2.

At

Attention

Each token weighs every earlier token to decide what matters.

This is why long context costs more compute.

Hx

Hallucination

Fluent but false output. The model predicts plausible text. It does not look facts up.

Fix with grounding (Book 2) and checks (Book 3).

Tr

How models are made

Pretraining on lots of text, then instruction tuning, then RLHF to make it a helpful assistant.

You will mostly use models, not train them.

Lt

Latency

Time to first token, then roughly a fixed time for each output token.

Output tokens are slower and pricier than input tokens.

Prompting basics

Treat a prompt like a spec for a smart new hire who has no context.

# system
You extract data from vendor invoices for an
accounts-payable team.

Rules:
- Use only the text inside <invoice> tags.
- Copy amounts exactly as written. Never compute them.
- If a field is missing, return null. Do not guess.
- Dates use ISO format: YYYY-MM-DD.

<example>
  <invoice>ACME Ltd · Inv #A-77 · Total $410.00</invoice>
  → vendor="ACME Ltd", invoice_number="A-77",
    total=410.00, due_date=null
</example>

# user
<invoice>{text}</invoice>
  • Give it a role and a goalWho it is working for, and what counts as a good answer.
  • Use tags to separate data from instructionsThe model can then tell what to read and what to obey.
  • Show 1 to 3 examplesExamples beat long descriptions, and they should cover edge cases.
  • Say what to do when unsure"Return null" lowers hallucination.
  • Long documents first, question lastThis usually works better for long inputs.
  • Version your promptsKeep prompts in files under git, not inline strings.

H

Self-check

Answer out loud before you open each one. These come up in interviews.

Why can the same prompt give different answers?

The model samples from a probability distribution. With temperature above 0 it picks among likely tokens. Even at 0, small numeric differences on the server can change a token, and every later token then changes too.

Why do LLMs struggle with arithmetic and exact IDs?

Numbers and IDs split into odd tokens, and the model predicts plausible digits instead of computing them. Let code do the math, and have the model copy values instead of calculating them.

The model "forgot" what the user said earlier. Why?

The API is stateless. You must send the history every turn. If you trimmed the history to fit the context window, the earlier turn is gone.

Why are output tokens more expensive and slower than input tokens?

Input is processed in parallel in one pass. Output is generated one token at a time, and each token needs its own pass through the model.

How do you get reliable JSON?

Force a tool or schema, validate with Pydantic, send validation errors back for a retry, and send anything that still fails to human review.

What is a hallucination, and what are two ways to reduce it?

Confident output that isn't supported by any source. Reduce it by grounding the model in retrieved documents and by allowing "unknown" or null. Then measure it with evals.

Embeddings: meaning as coordinates

Real embeddings have hundreds of dimensions. This 2-D sketch shows the idea.

Sketch with illustrative similarity scores. The query shares no exact words with "penalty interest accrues at 1.5%" but lands next to it. That's what keyword search misses.

cos

Cosine similarity

The angle between two vectors. 1 means the same direction, 0 means unrelated.

pgvector's <=> operator returns the cosine distance, which is 1 − similarity.

dim

Dimensions

Typically 384 to 3072 numbers per vector. More dimensions cost more storage but aren't always better.

The column type must match the model: vector(1024).

mdl

Choosing a model

Hosted models (Voyage, OpenAI, Cohere) or open ones (BGE, E5, GTE via sentence-transformers).

Check the MTEB leaderboard, then test on your own data.

!

One model per index

Query vectors and document vectors must come from the same model.

Changing models means re-embedding everything. Store the model name in a column.

def rrf(rankings: list[list[str]], k: int = 60) -> list[str]:
    scores: dict[str, float] = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1 / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)

hits = rrf([keyword_search(q, tenant), vector_search(q, tenant)])[:50]

J

Self-check

When would you not use RAG?

When the corpus fits in the context window (just send it, with caching). When you need exact live numbers (use a tool or SQL). When the goal is style or format (use prompting or fine-tuning).

Why combine keyword and vector search?

Vectors capture meaning but miss exact tokens such as invoice numbers, codes and names. Keywords catch exact strings but miss paraphrases. Fusing the two covers both cases.

What does a reranker do that the first search can't?

It reads the query and each candidate together (a cross-encoder) and scores how relevant they really are. That's too slow for 100k chunks but fine for 50.

How do you stop cross-tenant leaks in RAG?

Store tenant_id on every chunk and enforce the filter in the data access layer, never in the prompt. Add an automated test that queries as tenant A and asserts zero tenant B chunks come back.

Answers are wrong. What do you check first?

Whether the right chunk was retrieved at all. Log the retrieved chunks and look at them. Most problems are retrieval or chunking problems, not model problems.

def recall_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    return len(set(retrieved[:k]) & relevant) / len(relevant) if relevant else 1.0

def reciprocal_rank(retrieved: list[str], relevant: set[str]) -> float:
    for rank, chunk_id in enumerate(retrieved, start=1):
        if chunk_id in relevant:
            return 1 / rank
    return 0.0

LLM-as-judge, done properly

A judge is a model too, so it needs its own eval.

You are checking an answer for FAITHFULNESS.

<chunks>{chunks}</chunks>
<answer>{answer}</answer>

A claim is supported only if a chunk states it.
Reasoning from general knowledge does not count.

1. List each factual claim in the answer.
2. Mark each claim SUPPORTED or UNSUPPORTED
   and quote the chunk text that supports it.
3. Final line: PASS if every claim is
   SUPPORTED, otherwise FAIL.

Example numbers. Agreement is (30 + 13) / 50. Read the 7 disagreements, fix the rubric, and measure again.

  • 1–10 scalesThe scores drift and mean little. Use binary PASS/FAIL with a written critique.
  • Position biasIn A-vs-B comparisons, judges favour one position. Swap the order and run both.
  • Length biasJudges favour longer answers. Tell the judge length doesn't matter.
  • Self-preferenceA model rates its own output higher. Use a different model as the judge when you can.
  • Unvalidated judgeNever report judge scores without the agreement rate against human labels.

Self-check

How would you evaluate a RAG system?

Separately per stage. Score retrieval with recall@k and MRR against labelled chunks. Score generation with code checks (citations, schema, required facts) plus a validated judge for faithfulness and correctness. Use a golden set with unanswerable and adversarial cases, run it in CI, and add production failures to the set.

Why not just use a 1–10 judge score?

The scores are inconsistent and hard to act on. A binary pass/fail with a critique is more reliable, easier to compare with human labels, and tells you what to fix.

How do you know your judge is trustworthy?

Label a sample yourself, measure agreement and how many real failures the judge catches, read the disagreements, refine the rubric, and repeat until it's acceptable.

Your answer quality dropped after a prompt change. How would you catch that before shipping?

Run the eval suite in CI on each PR, compare scores against the main-branch baseline, and fail the build when any metric drops by more than a set tolerance.

What would you put on an LLM span?

Model, prompt version, tokens (input, output, cached), cost, time to first token, total latency, stop reason, retries, retrieved IDs, tenant and user feedback.

MAX_TURNS = 8

def run_agent(goal: str) -> str:
    messages = [{"role": "user", "content": goal}]
    for _ in range(MAX_TURNS):
        resp = client.messages.create(
            model=MODEL, max_tokens=2000, system=SYSTEM,
            tools=TOOLS, messages=messages,
        )
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")

        results = []
        for block in resp.content:
            if block.type == "tool_use":
                try:
                    output = dispatch(block.name, block.input)   # your code, your permission checks
                    results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
                except ToolError as e:                           # errors go back to the model as text
                    results.append({"type": "tool_result", "tool_use_id": block.id,
                                    "content": str(e), "is_error": True})
        messages.append({"role": "user", "content": results})

    raise AgentLimitError(f"No answer after {MAX_TURNS} turns")

Self-check

When is an agent the wrong choice?

When the steps are known in advance (use a chain), when mistakes are costly and hard to undo, or when latency and cost limits are tight. Agents are harder to test and less predictable.

What does the model actually do when it "calls a tool"?

It outputs a structured request (a name plus JSON arguments) and stops. Your code decides whether to run it, runs it, and sends back the result. The model never executes anything itself.

How do you defend against prompt injection?

No single fix works. Combine several: least-privilege tools, permission checks in code, human approval for risky writes, marking untrusted content, validating outputs, spending and row limits, and audit logs. Assume injected text will sometimes get through.

What is MCP and why does it matter?

An open protocol for exposing tools, resources and prompts to AI apps. You build an integration once and any compatible host can use it.

Your agent loops forever calling the same tool. What do you change?

Add turn and budget limits, return clearer tool errors, detect repeated identical calls, improve the tool description, and add the case to your agent eval set.

G

Common questions

Practise a 60-second answer for each one, out loud.

Walk me through a project you're proud of.

Problem → what you built (draw it) → how you measured it → one hard trade-off → the result in numbers → what you'd do next. Keep it to about 3 minutes, then let them dig in.

How do you reduce hallucinations?

Grounding with good retrieval, an explicit "not found" path, citations checked in code, a lower temperature for factual tasks, tools for exact data, and evals that measure faithfulness.

RAG vs fine-tuning vs long context?

RAG for private, changing knowledge that needs citations. Long context when the data is small and caching makes it cheap. Fine-tuning for format, style or a narrow high-volume task. Often a mix.

How do you know your LLM feature is working in production?

Traces with cost and latency, user feedback signals, sampled human review, a judge on sampled traffic, and alerts on drift. New failures go into the eval set.

Why move from backend engineering into AI?

Tie it to what you've seen in your work: real AI products need what you already do well (reliability, multi-tenancy, testing, finance accuracy), and you've built three projects to prove you can add the AI part.

Tell me about a time an AI system failed.

Use a real failure from your eval log: what broke, how you found it, the fix, and the eval you added so it can't come back.

# warm-up you should write in under 5 minutes
import math

def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    norm = math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b))
    return dot / norm if norm else 0.0

def top_k(query: list[float], docs: dict[str, list[float]], k: int = 5) -> list[str]:
    return sorted(docs, key=lambda d: cosine(query, docs[d]), reverse=True)[:k]
